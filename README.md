# Epicentro Gourmet

Trabajo Práctico Grupal, Hito 2 · Orientación a Objetos 2 · UNLA 2026 · **Grupo 12**

Sistema de gestión de festivales gastronómicos: unidades de venta (food trucks y puestos desarmables), su personal,
platos, pedidos, liquidación de haberes y reportes. Aplicación web con Spring Boot, Thymeleaf, Spring Security y MySQL.

## Cómo correr la aplicación

### Requisitos

- **JDK 21.** Con versiones más nuevas (por ejemplo JDK 27) Lombok no genera los getters/setters y el proyecto no compila.
- **MySQL 8** corriendo en `localhost:3306`.
- **IntelliJ IDEA** (o STS / VS Code) con el plugin de **Lombok** y el *annotation processing* habilitado
  (Settings → Build, Execution, Deployment → Compiler → Annotation Processors).

### 1. Variables de entorno

`application.yml` no tiene credenciales: las lee de variables de entorno.

| Variable | Ejemplo | Descripción |
|---|---|---|
| `DB_URL` | `jdbc:mysql://localhost:3306/epicentrogourmet?createDatabaseIfNotExist=true` | URL de la base. Con `createDatabaseIfNotExist=true` la base se crea sola |
| `USERNAME` | `root` | Usuario de MySQL |
| `PASSWORD` | *(tu contraseña de MySQL)* | Contraseña de MySQL |

En IntelliJ: **Run → Edit Configurations → + → Application**

- **Main class:** `com.unla.epicentrogourmet.EpicentroGourmetApplication`
- **Environment variables** (separadas por `;`):
  ```
  DB_URL=jdbc:mysql://localhost:3306/epicentrogourmet?createDatabaseIfNotExist=true;USERNAME=root;PASSWORD=tu_clave
  ```
- **No** tildar *Store as project file*, para que la contraseña no termine en el repositorio.

> En Windows, `USERNAME` ya existe como variable del sistema (tu usuario de Windows). Si no se carga en la Run
> Configuration, la aplicación intenta conectarse a MySQL con ese usuario y falla con `Access denied`.

Desde consola también funciona: `mvnw.cmd spring-boot:run` (Windows) o `./mvnw spring-boot:run`, con `JAVA_HOME`
apuntando al JDK 21 y las variables de entorno cargadas.

### 2. Crear la base y las tablas

Ejecutar la aplicación una vez. Hibernate (`ddl-auto: update`) crea la base y todas las tablas.
En la consola tiene que aparecer `Started EpicentroGourmetApplication`.

### 3. Cargar los datos de prueba

Con las tablas ya creadas, ejecutar [src/main/resources/sql/datos_prueba.sql](src/main/resources/sql/datos_prueba.sql)
sobre la misma base (por ejemplo desde MySQL Workbench). No hace falta reiniciar la aplicación.

El script vacía todas las tablas antes de insertar, así que se puede volver a ejecutar para volver a los datos iniciales.
Carga un festival activo del 01/10/2026 al 15/11/2026 con sus costos, tres unidades de venta, empleados de cada tipo,
platos y 300 pedidos.

### 4. Entrar

Abrir [http://localhost:8080/index](http://localhost:8080/index). Todos los usuarios de prueba tienen la contraseña `1234`.

| Usuario | Rol | Datos |
|---|---|---|
| `admin@epicentro.com` | Administrador | |
| `responsable1@epicentro.com` | Responsable | La Parrilla Rodante (food truck con electricidad) |
| `responsable2@epicentro.com` | Responsable | Tacos al Paso (food truck sin electricidad) |
| `responsable3@epicentro.com` | Responsable | Pastas de la Nonna (puesto desarmable) |
| `cocinero1@`, `ayudante1@`, `cajero1@epicentro.com` | Empleado | La Parrilla Rodante |
| `cocinero2@`, `lavaplatos2@`, `cajero2@epicentro.com` | Empleado | Tacos al Paso |
| `cocinero3@`, `cajero3@epicentro.com` | Empleado | Pastas de la Nonna |
| `ayudante3@epicentro.com` | Empleado | Dado de baja (no puede iniciar sesión) |
